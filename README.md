# 早期诈骗意图识别训练记录

本仓库整理项目中「通话文本反诈」的训练与实验工作：在长通话完整覆盖的基础上，尝试在诈骗后续操作发生之前，根据已经出现的证据识别诈骗意图。记录范围为 **M0 长文本基线 → M1 / E1-B 严格前缀训练 → E2-A/B/C/D 早期识别与时序报警实验**。

截至 **2026-10-19，当前保留的交付模型是 M1 / E1-B**。E2-B 的全文准确率最高，但各 E2 候选均未通过实时报警的联合替换条件，因此不能只按全文准确率决定上线版本。

本仓库是源码、配置与实验文档归档。**通话数据、逐条预测、封存Test及公司隐私评测数据不随仓库提供**；

## 2. 解决的问题

全文分类回答「整通电话是否涉诈」；早期识别还需要回答「到当前这一轮，证据是否已经充分」。一个模型可能在全文上正确，却在通话前几轮误报，或者等到转账等操作阶段才报警。因此这里分别观察全文分类、累计前缀检测、正常通话误报和报警时机。

- **tE**：首次诈骗证据充分的轮次，由既有裁定标注确定。
- **tA**：后续操作步骤边界，用于观察能否在该边界之前有效报警。
- **累计前缀**：截至第 t 轮的全部文本，只包含当时已经发生的内容。
- **k2**：连续两轮诈骗分数达到固定阈值 0.5，第二轮结束时触发报警。
- **有效检测**：tE 及以后有报警；**过早报警**：tE 以前曾报警。同一通电话可能同时满足两者，不能把两个比例直接相加。
- **normal 曾误报**：正常通话只要任一累计前缀报警，就记该通一次误报。

## 3. 模型方法与版本关系

文本先按 WordPiece 分块，再共享编码并汇聚全文证据。当前路线为 Route B，使用 `head_context_enhanced_chunks`：块长 320、重叠 64、最多 96 个头部上下文 token；融合 attention、top1、top2、last、mean 五路证据。`max_chunks=12` 是诊断阈值，**不是只保留前 12 块**。诈骗分数取独立二分类头 `softmax(binary_logits)[1]`，不使用历史 13 分类联合概率代替。

| 版本 | 主要改动 | 训练关系与当前定位 |
| --- | --- | --- |
| M0 / V361 | 长文本分块、头部上下文与证据汇聚 | 基线，也是后续训练的初始化来源 |
| M1 / E1-B | 60% 严格前缀 + 40% 原长文本回放；6500 次采样 | 从 M0 初始化，当前交付版本 |
| E2-A | V365 的 tE 边界前缀，正常前缀按长度和轮数匹配 | 从 M0 独立训练，保留作对比 |
| E2-B | 类别平衡、同场景正常匹配、tE/tE−1 局部边界损失 | 从 M0 独立训练；全文较好，未通过实时验收 |
| E2-C | 训练目标对齐 k2，惩罚证据不足阶段的连续高分窗口 | 从 M0 独立训练；未通过联合替换条件 |
| E2-D | 冻结 M1，用 10 项因果特征训练 193 参数门控 | 依赖 M1，只拦截已有 k2 报警；不是完整分类器 |

E2-A/B/C 不是基于上一版继续训练；均冻结骨干、二分类训练 1 轮、seed=202。E2-D 门控训练 20 轮。另有历史 E1-B 拒绝版，与当前 M1 必须区分，见 [模型索引](models/model_registry.json)。

## 4. 固定 Dev 上的结果

V365 Dev 共 200 通：其中 80 通正常、80 通诈骗参与二分类计分；诈骗含 early 15 通、explicit 65 通；另 40 通 ambiguous 仅作轨迹观察，不计二分类对错。原长文本 Long-Dev 为 240 通。

### 4.1 全文二分类，阈值 0.5

| 模型 | V365 Accuracy | V365 F1 | early 命中 | normal 误报 | Long-Dev Accuracy |
| --- | ---: | ---: | ---: | ---: | ---: |
| M0 | 90.00% | 89.61% | 9/15 | 5/80 | 100.00% |
| M1 / E1-B | 95.00% | 95.12% | 13/15 | 6/80 | 99.17% |
| E2-A | 95.63% | 95.71% | 13/15 | 5/80 | 99.17% |
| E2-B | 96.25% | 96.30% | 13/15 | 4/80 | 99.17% |
| E2-C | 95.63% | 95.65% | 12/15 | 4/80 | 99.17% |
| E2-D（复用 M1） | 95.00% | 95.12% | 13/15 | 6/80 | 99.17% |

E2-D 不改变全文分类器，这一行不是新训练的全文模型效果。

### 4.2 逐轮累计前缀，统一 k2

| 模型 | early 有效 | 全部诈骗有效 | normal 曾误报↓ | 诈骗过早报警↓ | 无过早报警且有效↑ | 严格 tA 前有效↑ | 延迟 P75（轮）↓ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| M0 | 13/15 | 76/80 | 11/80 | 51/80 | 25/80 | 58/65 | 1.25 |
| M1 / E1-B | 14/15 | 79/80 | 11/80 | 57/80 | 22/80 | 63/65 | 1.00 |
| E2-A | 14/15 | 79/80 | 14/80 | 59/80 | 20/80 | 64/65 | 1.00 |
| E2-B | 14/15 | 79/80 | 12/80 | 58/80 | 21/80 | 64/65 | 1.00 |
| E2-C | 14/15 | 79/80 | 11/80 | 56/80 | 23/80 | 64/65 | 1.00 |
| E2-D（M1 + 门控） | 13/15 | 78/80 | 8/80 | 30/80 | 48/80 | 57/65 | 2.00 |

延迟只统计已有效检出的通话；严格 tA 前有效的分母是全部 65 通 explicit，tE 前抢报不算有效成功。E2-D 减少了误报和抢报，也新增早期漏检并延后部分报警，因此仍保留 M1。完整口径、修改原因和限制见 [实验简报](reports/实验结果汇总.md) 与 [E2-D 复核](reports/E2D_实验完成与结论_20261016.md)。

## 6. 如何开始

```bash
git clone https://github.com/sleeeeeeeeeep/early-fraud-intention-identification-method.git
cd early-fraud-intention-identification-method
python3 tools/verify_export.py
```

训练与评测需要另行取得基础模型、V341 检查点及其 tokenizer、M0/M1 权重和授权 Train/Dev。先阅读 [复现说明](docs/REPRODUCING.md)；不要直接用归档脚本启动训练，也不要向现有输出目录覆写结果。部署使用独立环境和独立依赖，见 [deployment/README.md](deployment/README.md)。

## 7. 发布边界与来源

训练源目录约 32.6 GB，部署压缩包约 4.66 GB。仓库发布源码和汇总结论，未把大权重、训练对话、标注答案、逐条预测、历史压缩包或运行缓存放入 Git；具体对应关系见 [资源清单](docs/RESOURCES.md) 和 [导出说明](docs/EXPORT_NOTES.md)。代码中的机器路径已作适配，原始部署包的校验记录保留在 `deployment/provenance/`，不应拿它直接校验裁剪后的 GitHub 目录。

仓库用于项目工作记录。未额外添加开源许可证；源码、公司项目材料及第三方模型的使用权限以各自权利人授权为准。
