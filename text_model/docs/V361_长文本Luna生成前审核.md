## Luna 输出格式

每条任务输出一个纯 JSON 对象：

```json
{
  "task_id": "V361_TASK_0000",
  "turns": [
    {"speaker": "caller", "text": "..."},
    {"speaker": "callee", "text": "..."}
  ],
  "context_evidence": ["来电人逐字说出的身份或理由短语"],
  "risk_evidence": ["来电人逐字提出的可执行风险动作短语"],
  "scenario_summary": "不超过40字",
  "generation_notes": "不超过50字"
}
```

每条对话由 Luna 从零完整生成。`turns` 渲染为带 `来电人：/接电人：` 的音频文本；模型输入和 WordPiece 长度统计自动移除这些角色文字。

跨窗口样本使用 `context_evidence` 标注身份或理由，使用 `risk_evidence` 标注最终风险动作。校验器要求任何单个 320-token 窗口无法同时看到完整组合。

## 自动质量门槛

每条候选依次检查：

1. JSON、任务编号、轮次结构和来电人/接电人交替正确。
2. 去除角色文字后的 WordPiece 位于目标长度档。
3. 场景关键词、父类和 39 子类标签一致。
4. 诈骗风险动作由来电人真实提出，证据是对话中的逐字片段。
5. 正常样本形成官方核验或合法业务闭环，不推进转账、验证码、远控等风险动作。
6. Q1～Q4 证据位置与任务一致，跨窗口组合满足窗口隔离条件。
7. 对话无电话号码、网址、机械复读和明显模板填充。
8. 默认 320/64 分块范围覆盖全部 token，覆盖率为 100%。

自动通过后，再由独立 Luna 子代理审核自然度、标签、角色、否定、引用和反问逻辑。只有独立审核 `accept` 的候选进入最终槽位。

40 条冒烟放行标准：自动 READY 至少 32 条；每档长度 READY 率至少 70%；四类场景标签正确率至少 90%；角色标识保留率与模型 token 排除率均为 100%。未达到标准时先调整提示词和校验规则，再重新提交冒烟测试。
